# da Cecot Food — Identity Card

Custom **static** rebuild of dacecotfood.com (authentic Italian comfort-food pasta bar & street-food kitchen, Edmonton AB). Client project for **Unconventional Group**. This is the dacecot site — NOT a framework app, NOT another caterer.

## What it is / who it's for
- 13-page marketing site for da Cecot Food Inc. Production-ready: full SEO/AIO, structured data, responsive, accessible.
- Pages: home, menu, about/our-story, experiences (hub) + 5 sub-pages (sunday-pasta-classes, pasta-drop-in / pasta-shop, food-drink-experiences, private-events, catering), events, reservations, contact/visit-us, partnerships. (On-disk filenames include `our-story.html`, `pasta-shop.html`, `visit-us.html` — README lists older slugs; trust the generator output.) Plus `404.html`, `sitemap.xml`, `robots.txt`, `favicon.svg`.

## Brand / design system
- cream **#f9f7ef**, brown **#4a1e18**, olive **#374225**, terracotta **#ad5217**, gold **#c4a035**.
- **Playfair Display** (headings) + **Inter** (body). Experiences dropdown nav, FAQ accordions, alternating sections.
- dacecotfood.com itself is the quality bar referenced for other UGroup builds.

## Tech stack
- Plain static HTML/CSS/vanilla JS, NO runtime framework. Pages are **generated by a Node build script** — do NOT hand-edit the `.html` files (overwritten on build).
  - `.claude/build.js` — head/SEO, nav (Experiences dropdown), footer, schema helpers + the 7 core pages.
  - `.claude/build-experiences.js` — the 6 Experiences pages + final writer (sitemap, robots, 404, favicon, CSS minification).
- `css/styles.css` (source) → `css/styles.min.css` (generated, linked by pages). `js/main.js` = mobile nav, dropdown, FAQ accordion, scroll reveal, back-to-top, forms.

## Build
- `node .claude/build.js` regenerates all 13 pages + 404 + sitemap + robots + favicon + styles.min.css. **Edit the generator, then re-run** — editing `.html` directly gets overwritten.
- **Gate: `npm run gate`** (`npm test` → `npm run build`). Green before any claim of done. `npm test` runs three suites: `classes` (schedule, push planner, send.js confirmation emails), `closures` (one-off closures — including the server half, which is the half a browser check cannot cover) and `build-output`, which runs the real build and asserts on the generated HTML rather than on the generator.
- Beyond the static site there is a runtime layer: `api/` (Vercel serverless — **9 of the Hobby cap of 12**, so add actions to an existing handler rather than new files), `lib/orders` (Neon-backed submissions store + Resend mailer), `lib/cms` (content store/auth), `lib/classes` (class schedule + push planner) and `admin/` (Erika's site manager at `/admin`). Content lives in `content.json`, committed via the GitHub backend, so editing it IS editing live content.

## SEO / AIO
- Unique title/meta/canonical/OG/Twitter per page; one `<h1>` each; semantic structure; alt text + lazy/async images.
- JSON-LD: Restaurant (home), Restaurant+LocalBusiness (contact), Event (classes/drop-in), Service (experiences/private-events/catering), FAQPage, BreadcrumbList. "What is…" answer paragraphs + FAQ accordions for AI Overviews.

## PLACEHOLDERS / gotchas
- **Images** sourced from the client's Wix CDN (live-site real photos). The client's Google Drive originals folder is **private/download-locked (403)** — can't auto-import; see `DRIVE-PHOTOS.md` for filename/ID inventory + the access issue.
- The **contact form** (visit-us) is a front-end mockup (FormSubmit, no backend).
- **Reservations** route to the client's **Wix reservation page** — a live "Book a Table" button (opens Wix in a new tab). URL lives in `RESERVATION_BOOKING_URL` near the top of `.claude/build.js` (currently `https://dacecotfood.wixsite.com/my-site` — the bare `dacecotfood.wixsite.com` subdomain 404s; the published page is at the `/my-site` path). If that constant is ever blanked, the Reserve page falls back to a clearly-marked "booking launching shortly" pending state and steers guests to phone/email. (We previously scaffolded Square Appointments for this; that was dropped in favour of Wix on 2026-06-27.)
- **Pasta classes still use Square**, intentionally: Sunday Pasta Classes book + pay $95/guest via a Square checkout form (`square.link/u/mTkWSnl5`) on the Experiences page, and the Thursday drop-in uses a free FormSubmit reservation form. Only table reservations moved to Wix.
- **Class dates are generated, never hand-kept.** Classes run **weekly on Sundays**; `lib/classes/schedule.js` is the single source of truth and emits the next `classWeeksShown` (default 5) Sundays, skipping the first Sunday of each month (closed) and any `classBlackoutDates`. The generator, `/api/class-availability`, the submit-time validator in `api/send.js` and the admin all read it — if they ever disagree a guest can book a date the server then rejects. All date math is UTC; only "today" is Edmonton-local.
- **Bookings carry two dates:** `class_date` (1st choice, required) and `class_date_2` (2nd choice, optional). If a Sunday falls below `classMin` (default 4 guests), Erika hits **Move to 2nd choices** in the admin's Pasta Classes tab: each booking goes to *its own* 2nd choice (they scatter — that is deliberate, nobody lands on a date they didn't pick), and anyone with no usable backup keeps their slot and is emailed to rebook. `lib/classes/push.js` decides, `api/admin/orders.js` (`action:'push_class'`) applies. Covered by `npm test`.
- **The white `.booking` card inside an olive/brown section** needs dark-on-light text explicitly — the section-level rules lighten form text for dark backgrounds and otherwise bleed in, which once rendered labels cream-on-white at 1.14:1. See the `.section--olive .booking …` overrides in `css/styles.css`; anything added to the section-level rules needs a counterpart there.
- **Menu page — every menu currently reads "Coming soon" and no PDF is linked** (client's call, 2026-09-15). The four PDFs are still sitting in `/menus`, untouched. To bring one back: restore its `file` and flip `ready:true` in the `menuCards` array in `build.js`, re-run the build. The intro copy, the footnote under the cards and the menu FAQ answer (which is also in the FAQPage JSON-LD) all key off `MENUS_READY`, so they flip with it — `test/build-output.test.js` fails if a PDF is linked while the page still says coming soon, or the reverse. Lunch = `lunch-menu.pdf` (Erika's lunch menu), Dessert = `dessert-menu.pdf` (drink + dessert menu).
- **One-off closures** (`closedDates` in the CMS, `lib/cms/hours.js`) shut a SINGLE day for table reservations *and* pasta-shop pickups. Not the same mechanism as `hoursWed:'closed'`, which shuts every Wednesday — reaching for that to mean "closed today" closes the day forever. The list is embedded in both pickers at build time (`#service-hours`, `#pickup-hours`) and re-checked in `api/send.js` on submit, because a page left open overnight still carries yesterday's list. Past dates block nothing, so stale lines are harmless. **`2026-09-15` is currently listed.**
- **A Sunday class can be full without being cancelled**, and the two are different: `classBlackoutDates` REMOVES the date from the form; `classFullDates` keeps it there, greyed out and labelled "Fully booked". `schedule.js` flags it `full:true`, `isBookable` refuses it and `isFull` says why. It renders sold out at BUILD time (so it holds with JS off), is forced to zero seats in `/api/class-availability` (so the live fetch cannot re-open a date Erika closed), and is refused again in `api/send.js`. **`Sunday, September 20, 2026` is currently marked full.**
